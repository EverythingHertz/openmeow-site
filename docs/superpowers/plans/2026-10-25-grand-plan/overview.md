# openmeow.io — grand plan

## Context

The homepage is a long scroll generated by `scripts/build-world.mjs`: an arrival hero, eight pinned room sections with scroll-driven demonstrations, a capability directory and seven per-room catalogues. Every demonstration is synthetic and labelled illustrative. The scenes, the brand image and much of the copy depend on an orange-cat cast the user now finds silly; the film tour at `film.html` is the brass-and-amber suite the 2026-10-04 brief rejected.

**Measured against `main` at `7f69fc8`, 2026-10-25 (drift check H1).** The live page is **21,202 px at 1440×900 — 23.6 screens**, with the directory alone 8,370 px and beginning at 12,636 px. This supersedes the figures this plan was written against: at `52c9c21` it was 25,945 px at a 653 px viewport and 43,679 px at 900 px. **The page roughly halved** between those commits, so the problem is smaller than the plan first argued — though 23.6 screens is still an order of magnitude past a chooser, and the argument stands on its shape rather than its size.

**A regression also landed with that commit, and the plan does not fix it.** On `main`, clicking "Observatory" in the room nav sets `location.hash` to `#observatory` and **does not scroll at all**: start 0 px, finish 0 px, target at 10,635 px, settle 158 ms, with the visitor still looking at `arrival`. The section is `display: block` and `visibility: visible`, nothing is hidden, and `scroll-behavior` now computes to `auto` where it was `smooth`. At `52c9c21` the same click travelled 14,100 px in 1.6 s. Deep links into rooms are therefore broken on the live site. This is `main`'s to fix, not this branch's; it is recorded here because phase 9's redirect map and `testing.md`'s deep-link recovery row both assume `#room` anchors resolve.

The product underneath is strong: eight outcome rooms, **35 capabilities** with honest readiness (**19 working, 8 pilot, 8 in development**), three-step demonstrations per room, search and filters, tests, and a generator. This plan keeps all of that and changes what the visitor meets.

*Was 30 capabilities (15 / 8 / 7) when this plan was written. `7f69fc8` added five to `world-readiness.mjs`' `EXTRA_CAPABILITIES` — Review Desk, Visual Lookbook, All Terminals, Council and Challenge My Plan — taking the directory from 30 cards to 35, confirmed by counting `article[id^="cap-"]` on the live page. `world-model.mjs` still holds 23; the rest come from the readiness module.*

## What this plan builds

1. **One-screen chooser as the homepage.** Pick an outcome, see its workflow map. The leading map language is the **Transit system**: eight lines, stations are tools and steps, interchanges are shared tools, terminals are outcomes, a held task is a closed station. Selection lives in the URL hash. No travel: the panel swaps.
2. **A separate story page, long on purpose.** The film and the ascent move to `story.html`, where scrolling is the medium. Linked from the chooser as "Take the tour"; never the front door.
3. **A workflow graph for all eight rooms** as data, derived from what exists (`DEMOS.steps`, `CAPABILITIES`, `ROOMS.flow`) and extended with the three things the data lacks: shared tools, held states, human checkpoints.
4. **The Observatory instrument with one real run.** The strip chart renders committed run records; the first record is the 2026-10-25 deck-handoff run (metadata and hashes only, never content). The word "illustrative" comes off where a record is real.
5. **Cast retired, mark kept.** Cats leave scenes, alt text and copy before the first new page ships. The brand mark becomes the Dot from `agent-pet-mascot`, used functionally as the agent-state indicator. The name stays; a rename is the user's decision and out of scope.
6. **The drop chooser.** A client-side portal on the chooser — name, type and size only, nothing uploaded — whose tracker advances only on real events. Confirmed by the user on 2026-10-25 as a committed phase.
7. **Both colour schemes.** Light and dark from one token system — OS-aware, a persisted three-state toggle, no first-frame flash — with the Transit lines re-tuned per scheme. Requested 2026-10-25.

## Scope

**In:** `index.html` (chooser), `story.html`, new data module and renderers, the generator, CSS, tests, docs, `.gitattributes`, media policy. **Out:** the openmeow main repo (gateway, PR #47 engine) except the run-record contract this site consumes; new video generation (a costed decision recorded in phase 7, not taken here); any rename; content changes to products' claims or readiness.

## Constraints and alternatives considered

- **Chooser language.** *Transit* (chosen): the hero, picker and map are one object; scales to 30+ tools; selection is "where do you want to go". *Observatory instrument*: most credible for an observability product; kept as the Observatory room's native view and the "see a run" surface (phase 6). *Floor (isometric room)*: liked, but it is the cat world's geometry; retired with the cast. *Ledger (print)*: becomes the reduced-motion and print rendering of the same graph.
- **Page architecture.** *One app-like screen + one story page* (chosen) over *several sites* (fragments the catalogue) or *one long page with instant jumps* (a band-aid; the height is manufactured by the demo mechanic).
- **Media.** *Vector only on the chooser* (decided by the user, 2026-10-25): no room plates, no tower, no raster artwork of any kind on the homepage — the plates are cat scenes and the page is cast-free. The story page keeps the existing film as a labelled archive cut until a budget decision replaces it; the 18 modern plates and the 9-shot list stay documented (phase 7) and become unreferenced after phase 9, which is flagged there rather than resolved. No amber, per `.superdesign/design-system.md`.
- **Generator.** Extend the existing data modules and add a second build script rather than rewrite; `world.html` keeps the long document until parity is proven (phase 9).
- **Windows checkouts.** `core.autocrlf=true` converts the generated HTML and breaks the strict sync test at `tests/world.test.mjs:60`; phase 0 fixes this first.

## Principles this plan follows

There is no `brain/` in this compartment, under any `C:\Work\*`, or in `~/.claude`, so the planning skill's principle files cannot be cited. The plan is governed instead by the project's own recorded rules and the user's global rules:

- `docs/superpowers/specs/2026-10-04-room-scene-content-brief.md` and `2026-10-04-premium-world-pilot-design.md`: every product entry point reachable without the tour; scroll stays native and touch-friendly; reduced motion gets composed stills and equivalent links; no essential lettering baked into pixels; no amber dominance.
- `.superdesign/design-system.md` and `.superdesign/init/theme.md`: paper `#F3F4F0`, ink `#172B2A`, teal `#167C72`, graphite `#182328`, Space Grotesk; large editorial type, quiet borders, generous space.
- The intake engine's rules in `EverythingHertz/openmeow` PR #47 (`docs/product/2026-10-15-intake-portal/M0_PORT_NOTES.md`): bytes before opinions; the model's answer is advice; a tracker never advances on timers — adopted here as *show committed state or say it is a replay*.
- The user's global coding rules (`~/.claude/CLAUDE.md`): simplicity first, surgical changes, goal-driven execution with a verify step per phase.
